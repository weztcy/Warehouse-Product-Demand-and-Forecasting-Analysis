# 04. Data Cleaning

## Metadata

- Project Title: Warehouse Product Demand and Forecasting Analysis
- Selected Method: SQL
- Dataset Source: `dataset/Historical Product Demand.csv` (dimuat ke `raw.product_demand_raw`)
- Analysis Period: 2011–2017 (`1.048.575` baris)
- Execution Date: 2026-11-27
- Environment / Tool Versions: Windows 11, DuckDB 2.0.0, Python 3.x

## Tujuan Tahap

Menerapkan aturan pembersihan yang terstandarisasi dan dapat diaudit ke tabel terpisah `analytics.clean_product_demand` tanpa mengubah berkas CSV mentah maupun tabel `raw.product_demand_raw`.

## Metode dan Prosedur

1. Menjaga keutuhan berkas asli `dataset/Historical Product Demand.csv` dan tabel `raw.product_demand_raw`.
2. Mengeksekusi `script/04_cleaning_transformation.sql` (Bagian 1) untuk menormalkan teks, mengurai tanggal, mengonversi nilai bertanda kurung menjadi integer bertanda, dan menambahkan kolom indikator kualitas (`is_missing_date`, `is_parenthesized_demand`, `is_zero_demand`, `is_exact_duplicate_record`).
3. Mengekspor hasil bersih ke `dataset/product_demand_cleaned.parquet` dan memverifikasi kesamaan jumlah baris dan total unit.

## Data / Variabel yang Digunakan

- Sumber: `raw.product_demand_raw` (`1.048.575` baris)
- Output: `analytics.clean_product_demand` dan `dataset/product_demand_cleaned.parquet`

## Hasil

### 1. Data Cleaning Overview & 2. Identified Data Issues
Semua `1.048.575` baris dipertahankan di tabel bersih dengan atribut pelacakan lengkap agar setiap analisis lanjutan dapat menyaring cakupan secara konsisten dan dapat diaudit.

### 3. Missing Values Treatment
- **`Date` kosong (`11.239` baris di `Whse_A`):** Tidak dilakukan imputasi tanggal buatan (seperti interpolasi tanggal atau pengisian median) karena imputasi tanggal akan menciptakan lonjakan palsu pada bulan tertentu. Sebaliknya, baris diberi flag `is_missing_date = TRUE`, tetap dihitung dalam ringkasan gudang keseluruhan (`dim_warehouse`), dan dikecualikan dari agregasi deret waktu bulanan (`agg_monthly_demand`).

### 4. Duplicate Handling
- **`122.423` baris berulang pada 5 kolom:** Karena ketiadaan `Order_ID`, penghapusan langsung berisiko menghapus pesanan berulang yang sah (seperti pengiriman harian berulang dengan ukuran lot standar `500` atau `1.000`). Baris ditandai dengan `is_exact_duplicate_record = TRUE` (`ROW_NUMBER() > 1`) untuk keperluan uji sensitivitas, namun tetap dipertahankan.

### 5. Inconsistent Data Correction & 6. Invalid Values Handling
- **Spasi berlebih (`1.038.106` baris pada `Order_Demand`):** Dibersihkan dengan `TRIM()`.
- **Format bertanda kurung `(N)` (`10.469` baris):** Dideteksi via regex `^\(\d+\)$`, diberi flag `is_parenthesized_demand = TRUE`, lalu dikonversi menjadi bilangan negatif pada `order_demand_net`, `0` pada `order_demand_gross`, dan `ABS(N)` pada `order_demand_abs`.
- **Format tanggal `YYYY/M/D`:** Dikonversi menjadi tipe `DATE` via `TRY_STRPTIME(..., '%Y/%m/%d')::DATE`.
- **Permintaan bernilai nol (`28.681` baris):** Dipertahankan dengan flag `is_zero_demand = TRUE`.

### 7. Outlier Treatment
- Tidak ada pemangkasan (*winsorizing*) atau penghapusan nilai ekstrem (`maksimum 4.000.000`, `minimum -999.000`) karena seluruh nilai berada pada skala SKU industri/grosir yang wajar dan memengaruhi perhitungan kapasitas gudang sesungguhnya.

### 8. Data Cleaning Rules

| Aturan | Kondisi | Aksi pada `analytics.clean_product_demand` | Baris Terdampak |
|---|---|---|---|
| R-01 | `TRIM(order_demand_raw)` cocok `^\(\d+\)$` | `is_parenthesized_demand = TRUE`, `order_demand_net = -N`, `order_demand_gross = 0` | `10.469` |
| R-02 | `TRIM(order_demand_raw)` cocok `^\d+$` | `order_demand_net = N`, `order_demand_gross = N` | `1.038.106` |
| R-03 | `order_date_raw IS NULL` | `is_missing_date = TRUE`, `order_date = NULL` | `11.239` |
| R-04 | `order_demand_net = 0` | `is_zero_demand = TRUE` | `28.681` |
| R-05 | `ROW_NUMBER() OVER (5 kolom) > 1` | `is_exact_duplicate_record = TRUE` | `122.423` |

## Interpretasi dan Implikasi

Dengan memisahkan `order_demand_gross` dan `order_demand_net` serta menandai `is_missing_date`, perhitungan deret waktu dan peramalan terlindung dari penyusutan volume artifisial akibat retur tanpa tanggal maupun pencampuran data parsial.

## Validasi / Reproducibility

Pernyataan `assert raw_cnt == clean_cnt == 1048575` dan `assert gross - return == net` dijalankan otomatis setiap kali `script/run_sql_pipeline.py` dieksekusi.
