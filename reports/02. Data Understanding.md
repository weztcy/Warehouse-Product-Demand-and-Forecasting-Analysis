# 02. Data Understanding

## Metadata

- Project Title: Warehouse Product Demand and Forecasting Analysis
- Selected Method: SQL
- Dataset Source: `dataset/Historical Product Demand.csv`
- Analysis Period: 2011–2017 (`2011-01-08` s.d. `2017-01-09`)
- Execution Date: 2026-11-27
- Environment / Tool Versions: Windows 11, DuckDB 2.0.0, Python 3.x

## Tujuan Tahap

Mendeskripsikan sumber data, struktur berkas, dimensi baris dan kolom, arti tiap variabel, tipe data mentah vs target, granularitas catatan, relasi antar-entitas, cakupan temporal, serta penilaian awal sebelum profiling mendalam.

## Metode dan Prosedur

1. Membaca metadata berkas fisik `dataset/Historical Product Demand.csv` (ukuran berkas `51.253.380` byte / ~48,88 MB).
2. Memuat seluruh kolom sebagai `VARCHAR` ke tabel `raw.product_demand_raw` melalui `script/01_schema.sql` dan `script/02_load_data.sql` untuk menjamin data asli tidak berubah.
3. Menjalankan kueri inspeksi kardinalitas, cakupan tanggal, dan relasi entitas melalui `script/03_data_quality.sql`.

## Data / Variabel yang Digunakan

Seluruh `5` kolom dari `dataset/Historical Product Demand.csv` plus kolom teknis `row_id` pada tabel mentah.

## Hasil

### 1. Data Source
- Berkas tunggal CSV: `dataset/Historical Product Demand.csv` (lokasi awal di root proyek, dipindahkan tanpa modifikasi isi ke folder `dataset/`).
- Ukuran berkas: `51.253.380` byte (`~48,88 MB`).

### 2. Dataset Description
Dataset mencatat transaksi permintaan pesanan produk harian/per-baris di tingkat SKU, gudang, dan kategori produk lintas tahun `2011` hingga awal `2017`.

### 3. Dataset Structure & 4. Data Dimensions
- **Total Baris Data:** `1.048.575` baris (tidak termasuk header).
- **Total Kolom:** `5` kolom sumber (`Product_Code`, `Warehouse`, `Product_Category`, `Date`, `Order_Demand`).
- **Catatan Struktural Kritis:** Jumlah `1.048.575` baris tepat sama dengan batas maksimum baris lembar kerja Excel (`1.048.576` baris dikurangi 1 baris header). Hal ini merupakan sinyal kuat bahwa dataset sumber pernah diekspor atau dipotong pada batas baris spreadsheet dan perlu dicatat sebagai potensi risiko *truncation*.

### 5. Variable Description & 6. Data Types

| Kolom Sumber | Tipe Mentah | Tipe Target Bersih | Kardinalitas Unik | Deskripsi & Contoh Nilai |
|---|---|---|---|---|
| `Product_Code` | `VARCHAR` | `VARCHAR` | `2.160` | Kode unik SKU produk (contoh: `Product_0993`, `Product_1359`) |
| `Warehouse` | `VARCHAR` | `VARCHAR` | `4` | Kode gudang (`Whse_J`, `Whse_S`, `Whse_C`, `Whse_A`) |
| `Product_Category` | `VARCHAR` | `VARCHAR` | `33` | Kode kategori produk (contoh: `Category_019`, `Category_028`) |
| `Date` | `VARCHAR` | `DATE` | `1.729` | Tanggal format `YYYY/M/D` (contoh: `2012/7/27`; `11.239` nilai kosong) |
| `Order_Demand` | `VARCHAR` | `BIGINT` | `3.828` | Kuantitas unit permintaan sebagai string dengan spasi akhir (`'100 '`) atau tanda kurung (`'(100)'`) |

### 7. Data Granularity
- Granularitas mentah: **1 baris catatan permintaan** (*order demand line*) untuk kombinasi `(Product_Code, Warehouse, Product_Category, Date)`.
- Karena tidak ada kolom `Order_ID` atau nomor transaksi, satu SKU pada gudang dan tanggal yang sama dapat muncul pada lebih dari satu baris.

### 8. Data Relationships
- **`Product_Code` → `Product_Category` (`N:1` ketat):** Hasil verifikasi SQL (`03_data_quality.sql` kueri 5) menunjukkan `multi_category_skus = 0` dari `2.160` SKU. Setiap SKU memetakan ke tepat satu kategori.
- **`Product_Code` ↔ `Warehouse` (`M:N`):** Hasil kueri 6 menunjukkan `1.670` SKU (`77,31%`) hanya muncul di `1` gudang, `319` SKU di `2` gudang, `143` SKU di `3` gudang, dan `28` SKU di seluruh `4` gudang.

### 9. Data Coverage
- Rentang tanggal keseluruhan: `2011-01-08` s.d. `2017-01-09` (`1.729` tanggal unik).
- Sebaran baris per tahun:
  - `2011`: `640` baris (`7` bulan aktif: `2011-01-08` s.d. `2011-12-31`) — **parsial**
  - `2012`: `203.635` baris (`12` bulan penuh)
  - `2013`: `218.298` baris (`12` bulan penuh)
  - `2014`: `216.404` baris (`12` bulan penuh)
  - `2015`: `209.661` baris (`12` bulan penuh)
  - `2016`: `188.645` baris (`12` bulan penuh)
  - `2017`: `53` baris (`1` bulan aktif: `2017-01-02` s.d. `2017-01-09`) — **parsial**
  - Tanpa tanggal (`NULL`): `11.239` baris (`100%` di `Whse_A`).

### 10. Initial Data Assessment
Dataset kaya akan riwayat multi-tahun (`2012–2016` lengkap 60 bulan untuk seluruh `4` gudang), namun memerlukan penanganan eksplisit terhadap: (1) spasi akhir dan format tanda kurung pada `Order_Demand`, (2) `11.239` baris tanpa tanggal pada `Whse_A`, (3) baris berulang 5 kolom tanpa kunci primer, dan (4) batas parsial `2011` & `2017`.

## Interpretasi dan Implikasi

Relasi `Product_Code -> Product_Category` yang bersih (`0` konflik) memudahkan pembangunan tabel dimensi produk dan kategori yang konsisten, sementara keberadaan `2011` dan `Jan 2017` yang sangat tipis mengharuskan isolasi jendela penuh `2012–2016` untuk analisis deret waktu.

## Validasi / Reproducibility

Seluruh angka dimensi, relasi, dan cakupan tahunan dihasilkan langsung oleh `script/02_load_data.sql` dan `script/03_data_quality.sql` terhadap `raw.product_demand_raw`.

## Keterbatasan dan Asumsi

- Arti bisnis nilai bertanda kurung dan baris nol belum terverifikasi dengan pemilik sistem sumber (*Perlu konfirmasi* apabila akan dijadikan dasar penagihan/akuntansi; dalam analisis ini diperlakukan sebagai retur/penyesuaian negatif).
- Batas baris tepat `1.048.575` menandakan kemungkinan pemotongan data pada batas spreadsheet (`Belum diketahui` apakah ada baris setelah tanggal `2017-01-09` yang terpotong).
